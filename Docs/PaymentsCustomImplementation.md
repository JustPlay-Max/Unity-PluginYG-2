# Собственная обработка покупок

Если вы пишете свой магазин, вместо готовых компонентов используйте API Payments.
Выключите **AutoConsume**: оплаченная покупка придёт в `YG2.onPurchaseReceived`
как `PaymentTransaction` с полями `productID` и `purchaseToken`.

`YG2.GetPendingPurchases()` возвращает оставшиеся покупки через
`YG2.onGetPendingPurchases`. Запрос ничего не выдаёт и не подтверждает.
`YG2.ConsumePurchaseByToken(token)` подтверждает одну покупку без повторного события выдачи.

## Пример

`Payments/Example/Scripts/ManualPaymentsExample.cs` содержит всю логику примера
и дополнительные поля `SavesYG`. Используется модуль **Storage**.

Добавьте компонент на объект и заполните:

- **Coins Product ID** — ID товара, который даёт монеты и может покупаться повторно.
- **Coins Per Purchase** — количество монет за покупку.
- **Permanent Product ID** — ID постоянного товара, например отключения рекламы.

В Inspector поля ID должны соответствовать товарам вашего каталога.
Для проверки в редакторе укажите такие же ID в симуляции Payments.

Публичные методы можно привязать к кнопкам или вызвать через контекстное меню
компонента в Play Mode:

| Метод | Действие |
| --- | --- |
| `BuyCoins()` | Купить монеты |
| `BuyPermanent()` | Купить постоянный товар |
| `RestorePurchases()` | Проверить оставшиеся покупки и повторить незавершённое подтверждение |

`Start()` вызывает `RestorePurchases()`. Новая покупка и восстановление используют
один обработчик. Предполагается, что сохранения уже загружены.

## Выдача и подтверждение

Для монет скрипт проверяет токен, добавляет награду и токен в `YG2.saves`, затем
вызывает `YG2.SaveProgress(callback)`. Только при `success == true` покупка
подтверждается. Повторный токен не добавляет монеты: повторяется сохранение
и подтверждение. Очередь не позволяет двум обработчикам одновременно менять данные.

Постоянный товар отмечается в сохранении, но не консумируется: платформа
продолжит возвращать его для восстановления.

При ошибке записи или подтверждения повторите `RestorePurchases()`.
Состояние видно через свойства `Coins`, `PermanentUnlocked` и сообщения в консоли.

Для Яндекс Игр используйте облачное сохранение Storage. Новый callback ждёт
результата отправки, даже если обычная настройка `flush` выключена.
Подробности — [callback сохранения](StorageSaveCallback.md).

Пример показывает обработку в одном экземпляре игры. Для своей игры сохраняйте
награду и обработанные токены вместе; учитывайте размер журнала токенов.
