# Результат сохранения прогресса

У `YG2.SaveProgress` появилась необязательная перегрузка с callback:

```csharp
YG2.SaveProgress(success =>
{
    if (success)
        Debug.Log("Прогресс сохранён");
    else
        Debug.LogWarning("Не удалось подтвердить сохранение");
});
```

Существующий вызов `YG2.SaveProgress()` работает как раньше.

Callback вызывается один раз для своего запроса. Несколько облачных сохранений
могут завершиться в разное время, каждый получит собственный результат.

## Что означает success

- **Облако Яндекс Игр:** успешный ответ `player.setData` с `flush: true`.
  Эта перегрузка ждёт отправки данных на сервер независимо от настройки `flush`.
- **Локальное сохранение на ПК и мобильных устройствах:** `PlayerPrefs.SetString`
  и `PlayerPrefs.Save` завершились без исключения.
- **Локальное сохранение в WebGL:** `localStorage.setItem` завершился без ошибки.
- **Unity Editor:** файл симулированного сохранения успешно записан.

Если включено облако Яндекс Игр, одной локальной записи недостаточно для
положительного результата: callback ждёт облако. При ошибке любой из включённых
записей возвращается `false`.

Без инициализации плагина или без выбранного хранилища возвращается `false`.
В редакторе, как и прежде, используется файл симулированного сохранения.

Для остальных WebGL-платформ облачный callback пока не реализован: запрос
передаётся существующей реализации, но результат callback будет `false`
с предупреждением об отсутствии подтверждения. Старые вызовы без callback
продолжают работать. На нативных платформах стандартный локальный fallback
поддерживает callback без изменений платформенного SDK.

Результат отражает завершение операции соответствующего хранилища. Он не
обещает защиту от повреждения накопителя, последующего удаления данных или
перезаписи прогресса другой вкладкой либо устройством.

## Подтверждение покупки после записи

Сначала измените награду и отметьте токен в `YG2.saves`, затем:

```csharp
YG2.SaveProgress(success =>
{
    if (success)
        YG2.ConsumePurchaseByToken(token);
});
```

При ошибке не подтверждайте покупку. Повторное получение того же токена
должно повторять сохранение и подтверждение без повторной выдачи награды.
